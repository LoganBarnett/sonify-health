* v0.42.0
** Added
1. Patches gain four controls: a parametric EQ band (~eq_hz~, ~eq_db~, ~eq_q~),
   an ~envelope_curve~ that bends the attack, decay, and release ramps, a
   ~spread~ that doubles the main voice into two detuned copies, and a ~hiss~ of
   white noise added after the filter.  No action needed.
2. A new example, ~examples/llm-coding-agents.toml~, sonifies Claude Code
   session activity with a drone fit to the Iron Seed ~Slash~ sample that grows
   with the number of busy sessions.  It needs ~jq~ on the daemon's path.
** Fixes
** Breaking
1. For library consumers: ~Patch~ and ~PatchOverrides~ gained six fields and
   ~ContinuousControls~ five, so literal constructions without
   ~..Default::default()~ must add them.
2. A patch whose ~fm_depth~ is above 0 may sound slightly different, as it
   already did whenever a note was added or a filter engaged.  No action needed.
** Maintenance
* v0.41.0
** Added
1. Patches have a new ~sub_phase~ parameter: where the sub-octave starts in its
   cycle relative to the main oscillators, which shapes the tone once ~drive~ is
   above 1.  No action needed.
** Fixes
1. A patch now sounds the same every time it is built: engaging a filter, adding
   a note, or a periodic rebuild no longer changes its tone.  No action needed.
2. Clock and loop playback no longer carry a DC offset from heavy ~drive~;
   continuous playback already blocked it.  No action needed.
3. Continuous playback now honours ~detune~ and ~harshness_offset~ and applies
   vibrato and FM to the sub-oscillator, as clock and loop playback already did.
   See Breaking for the audible effect.
4. ~downsample~ now runs at its nominal rate on every output device, so a patch
   no longer buzzes differently on 44.1 kHz and 48 kHz devices.  No action
   needed.
5. ~reverb_mix~ is now the wet/dry blend its description promised, and
   ~reverb_mix = 0~ is dry.  See Breaking.
** Breaking
1. Every patch sounds quieter and darker: ~reverb_mix~ is now a dry/wet blend
   over a fixed hall and ~reverb_mix = 0~ is dry.  Raise ~amplitude~ or the
   master volume and lower ~reverb_mix~ (0.1-0.3 is a typical room); one-shot
   heartbeats play about 1.8 s longer for the tail.
2. A patch with ~drive~ above 1 and ~sub_octave~ above 0 may sound slightly
   different from an earlier session: oscillators now start from a fixed phase
   rather than one that varied with the graph.  There is no single old sound to
   restore.
3. Clock and loop patches with heavy ~drive~ lose their DC offset and about 1 dB
   at 20 Hz, matching continuous playback.  Nothing restores the offset.
4. A continuous-mode patch that sets ~detune~ or ~harshness_offset~, or combines
   ~sub_octave~ with vibrato or FM, will audibly change.  Zero ~detune~ and
   ~harshness_offset~ to restore those two; the sub-oscillator change has no
   opt-out short of zeroing the modulation.
5. Patches tuned by ear with ~downsample~ between roughly 0.1 and 0.5 change the
   most, because those settings were silently rounded to a whole-number
   decimation.  To keep an old rate, set ~downsample~ to ~log2(100000 /
   (device_rate / N)) / 8~ for the N it was rounding to; about 0.27 keeps the
   22.05 kHz that 0.21 produced on a 44.1 kHz device.
6. For library consumers: ~Patch~, ~PatchOverrides~, and ~StructuralParams~
   gained a ~sub_phase~ field, so literal constructions without
   ~..Default::default()~ must add it, and ~continuous_graph~ takes a noise seed
   as its last argument.

* v0.39.0
** Fixes
1. The nix-darwin service now starts in its default Unix-socket mode.  No action

** Maintenance

* v0.38.0
** Added
1. Patches have a new ~lowpass~ parameter that cuts high frequencies.  No action
   needed.
** Fixes
1. The Stop-hook review gate no longer lets synthetic transcript entries (its
   own block feedback, background task notifications) reset its per-turn round
   budget, so its bounded-rounds escape hatch works again in harnesses that emit
   such entries.  No action needed.
2. Continuous playback no longer silently ignores ~highpass~; see the Breaking
   section for the audible impact.
3. Audio can no longer destabilize into noise or silence on devices running at
   low sample rates (Bluetooth headsets in call mode, some USB audio).  No
   action needed.
** Breaking
1. Continuous playback no longer ignores ~highpass~: an existing continuous-mode
   patch that sets it will audibly change.  Zero the parameter to restore the
   old sound.
2. For library consumers, grouped by the struct or API you use:
   - ~Patch~ / ~PatchOverrides~: gained a ~lowpass~ field; literal constructions
     without ~..Default::default()~ must add it.
   - ~ContinuousControls~ / ~StructuralParams~: gained fields, and their
     constructors now take the output device's sample rate.
   - ~PatchParamMeta~: gained a ~logarithmic~ field.
   - Audio graph constructors and ~AudioOutput::play~ / ~play_for~: now take the
     sample rate; ~play~ takes a graph-builder closure receiving it.
** Maintenance
1. Synced the project to rust-template v0.102.0, including a daily scheduled
   dependency-bump workflow and a rebuilt contributor code-review gate.  No
   action needed.

* v0.2.0
** Added
1. A heavy sync with ~rust-template~ brings in a load of shared behavior as well
   as this very change log.
2. Releases now ship prebuilt ~sonify-health~ and ~sonify-health-server~
   binaries for Linux (glibc and static musl) and macOS (Intel and Apple
   Silicon), attached to each GitHub release with a SHA-256 digest and a
   build-provenance attestation.  A one-command ~curl ... | sh~ quick start
   (~install.sh~) downloads the latest release for the platform, lays down the
   Star Trek bridge preset, and runs it — a working, zero-configuration first
   run.  The README also documents the underlying ~curl~ download, ~cargo
   install~, and Nix routes.
** Fixes
1. The daemon now recovers from a silently stalled audio stream.  After a macOS
   output-device change that left the render callback un-pumped without a cpal
   error, playback would stay silent indefinitely; a liveness watchdog now
   detects the stall and rebuilds the stream on the current default device.
   Callback health is exposed via the new ~audio_seconds_since_last_callback~
   and ~audio_callback_stalls_total~ metrics.
